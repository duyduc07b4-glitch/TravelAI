TAB 4 · Self-Healing Itinerary

Phân tích chức năng “Tự chữa lịch trình”

Mục tiêu: khi thời tiết xấu hoặc có sự cố (mưa lớn, bão, nắng gắt...), AI tự đề xuất lịch trình thay thế mà người dùng không cần chỉnh sửa thủ công.

Khó khăn chính

  • Dữ liệu đầu vào không đầy đủ: chỉ biết “mưa” hay “xấu” thì chưa đủ để đổi lịch đúng.
  • Phân loại hoạt động: cần biết hoạt động nào ngoài trời, trong nhà, di chuyển xa, hay phụ thuộc giờ mở cửa.
  • Giữ logic lịch trình: thay một điểm phải không phá vỡ thứ tự, tuyến đường, ngân sách và bối cảnh nhóm.
  • AI dễ bịa thay thế: model local có thể đề xuất điểm nghe hợp lý nhưng không phù hợp thực tế.
  • JSON / schema dễ lỗi: nếu output sai format thì UI khó render và khó cập nhật tự động.
  • Thiếu xác thực thời gian thực: giờ mở cửa, tình trạng đóng/mở, quãng đường thực tế không chắc chắn.
  • Xử lý fallback: khi Open-Meteo hoặc Ollama lỗi, vẫn phải có phương án dự phòng.

Nên triển khai thế nào

1. Chuẩn hóa input
Nhận vào itinerary hiện tại, tình huống thời tiết, điểm đến, mức độ khẩn cấp.
2. Phân loại activity
Gắn nhãn cho mỗi hoạt động: indoor / outdoor / transit / food / shopping / backup.
3. Tạo luật thay thế
Ưu tiên indoor khi mưa, ưu tiên gần vị trí hiện tại, giữ cùng khung giờ nếu có thể.
4. Gọi LLM với schema chặt
Yêu cầu trả JSON gồm replacements + updated_itinerary + reason.
5. Validate trước khi render
Kiểm tra mảng hợp lệ, field đủ, và độ dài hợp lý rồi mới cập nhật UI.
6. Hiển thị diff rõ ràng
Cho người dùng thấy “đã đổi gì”, “vì sao đổi”, và lịch trình mới.

Flow đề xuất

Itinerary hiện tại
      ↓
Weather / incident input
      ↓
Rule-based filtering
  - bỏ hoạt động outdoor
  - ưu tiên indoor gần đó
  - giữ chi phí / tuyến đường
      ↓
LLM sinh phương án JSON
      ↓
Validate JSON + fallback
      ↓
Render thay đổi + lịch trình mới

Gợi ý cấu trúc dữ liệu

{
  "incident": "Buổi sáng mưa lớn",
  "updated_itinerary": ["Aquarium", "Museum", "Shopping Mall"],
  "replacements": [
    {
      "original": "Beach",
      "replacement": "Aquarium",
      "reason": "Hoạt động trong nhà, phù hợp khi mưa"
    }
  ]
}

Tiêu chí thành công

Đúng ngữ cảnh
Thay thế phù hợp với mưa / nắng / bão.
Ít lỗi schema
JSON luôn render được, có validate.
Không phá lịch
Giữ được thứ tự, chi phí và trải nghiệm.

Khuyến nghị triển khai trong code hiện tại

  • Giữ Open-Meteo làm nguồn thời tiết thật, nhưng chỉ dùng như tín hiệu kích hoạt.
  • Tách logic thành 2 lớp: rule-based để lọc hoạt động không phù hợp, rồi LLM để viết lại lịch trình.
  • Chỉ chấp nhận output JSON đã validate; nếu fail thì hiển thị fallback thay vì sửa âm thầm.
  • Cho phép người dùng xem “thay đổi” và “lịch trình mới” riêng biệt, đúng như mockup trong ảnh.
  • Ưu tiên các thay thế an toàn: aquarium, museum, shopping mall, indoor activities, café.

Tóm tắt ngắn

Đây là một bài toán kết hợp giữa dữ liệu thời tiết, rule-based logic và LLM. Khó nhất là giữ cho lịch trình vừa “thông minh” vừa “đúng thực tế”.

Cách làm tốt nhất là: phân loại hoạt động → lọc theo sự cố → sinh phương án thay thế → validate → render diff.
